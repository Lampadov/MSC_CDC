# Осциллограф в браузере для К1986ВЕ92FI

Плата определяется как USB-диск. На диске лежит страница осциллографа: откройте `index.htm` прямо с флешки в браузере на базе Chromium, нажмите **Подключить плату**, и страница по WebUSB показывает сигнал, который АЦП платы измеряет на входе. Ничего устанавливать и скачивать не нужно: ни драйверов, ни сервера, ни интернета.

> Пример не проверен на железе: он собран без компилятора ARM, имена функций SPL для АЦП взяты по памяти. Сверьте их с вашей версией библиотеки (`MDR32FxQI_adc.h`). Логика захвата проверена на ПК тестом `tools/scope_test.c`.

## Что нужно

- Плата К1986ВЕ92FI (или другая ВЕ9х с USB) и USB-кабель.
- Вход: канал 7 АЦП (`PD7`). На отладочной плате он идёт на разъём внешнего сигнала или на подстроечный резистор, выбор делает перемычка (`EXT_CON` / `TRIM`). Если на вашей плате сигнал заведён на другой канал, измените `SCOPE_ADC_CHANNEL`, `SCOPE_ADC_PORT`, `SCOPE_ADC_PIN` в начале `main.c`.
- Напряжение на входе строго 0…3,3 В. Отрицательное и выше питания выведет вход из строя. Для других сигналов нужен делитель или усилитель.
- Браузер на базе Chromium (Chrome, Edge, Opera, Яндекс Браузер). В Firefox и Safari WebUSB нет.

## Запуск

1. Откройте `USB_SCOPE.uvprojx` в Keil, соберите и прошейте плату. Если проект не помещается в 32 КБ бесплатной версии, уберите светодиоды и лишние окна длиной 1120 точек (`SCOPE_MAX_SAMPLES` в `src/scope.h`).
2. Подключите плату к USB. Появится диск `Milandr OSC` (только чтение) с файлами `index.htm`, `app.js`, `README.TXT`.
3. Откройте `index.htm` с этого диска, нажмите **Подключить плату**.

## Как это устроено

- Составное устройство: интерфейс 0 - флешка (MSC, EP1 OUT / EP2 IN), интерфейс 1 - vendor-класс для WebUSB (одна точка EP3 IN). Команды уходят vendor-запросами на нулевую точку.
- АЦП1 работает в непрерывном режиме, прерывание по окончании преобразования отдаёт каждый отсчёт в `scope_sample()` (`src/scope.c`). Там кольцевой буфер с предзаписью: пятая часть окна - до точки синхронизации, остальное - после.
- Синхронизация по фронту или спаду с гистерезисом 24 кода. Авто: если события нет, кадр уходит сам после двух окон. Ждущий: кадр только по событию.
- Частоту дискретизации плата не берёт из расчёта: она измеряет время между первым и последним отсчётом по SysTick и передаёт в каждом кадре. Страница строит по ней шкалу времени и частоту сигнала.
- Скорость выбирается делителем тактовой частоты АЦП (8…256). При тактировании АЦП от ядра 80 МГц и делителе 8 ожидается порядка 350 квыб/с, точное значение покажет страница.

Непрерывный режим (в списке «Режим» страницы): синхронизации нет, АЦП пишет отсчёты в FIFO на 1024 штуки, главный цикл отправляет их кусками по 128 отсчётов, страница рисует бегущую осциллограмму. На быстрых развёртках поток (около 0,75 МБ/с при 357 квыб/с) может не пройти по USB FS: тогда FIFO переполняется, лишние отсчёты отбрасываются, а страница считает кадры с потерями (флаг в кадре, бит 2). Без потерь рассчитывайте на делитель 16 и медленнее (около 180 квыб/с и ниже).

Команды (vendor-запрос на интерфейс 1, `wValue`):

| bRequest | Биты wValue |
|---|---|
| `0x11` | 0…3 номер скорости, 4…10 число отсчётов / 16 |
| `0x12` | 0…11 уровень синхронизации, 12 спад, 13 ждущий режим, 14 пуск, 15 непрерывный режим |

Кадр (EP3 IN, little-endian): `A5 5A` `флаги (бит 0 синхронизация, бит 1 непрерывный, бит 2 были потери)` `скорость` `число отсчётов (2)` `номер кадра (2)` `частота дискретизации, Гц (4)` `отсчёты по 2 байта (12 бит)`.

Образ диска создаёт `tools/make_disk.py` из каталога `web/`. После правки страницы выполните `python tools/make_disk.py` и пересоберите проект. Имена на диске только 8.3: `web/index.html` лежит как `index.htm`.

## Если Windows не подключила WinUSB

Windows запоминает результат для связки VID/PID/bcdDevice. Если ранее плата уже определялась с другими дескрипторами, измените `USB_PID` в `src/usb_descriptors.c` и пересоберите образ.
